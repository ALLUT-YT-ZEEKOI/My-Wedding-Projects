1. Project overview

LuxeHalls is a multi-role marketplace for wedding and banquet halls. Customers discover and book venues. Vendors list halls, manage availability, and handle bookings. Super Admin governs the platform — vendor approvals, halls, payments, offers, support, and reports.

3. Customer — complete features

The customer side is the public marketplace plus a logged-in account area.

3.1 Public discovery (no login required)

  • Luxury homepage — editorial hero, glassmorphic search, event types (Wedding / Reception / Engagement), featured and popular halls, active offers, approved reviews.
  • Search by location and date — city/area text search, optional GPS “current location” with radius (default 25 km using hall lat/lng), event date that hides halls already booked for a full day.
  • Venue collection — magazine-style grid of live halls only (status = live).
  • Hall profile — cover photo, type, rating/reviews, address, capacity, slot pricing (morning / evening / full day), security deposit, policies (timing, veg/non-veg, catering, alcohol, music), Leaflet map, date + slot picker that greys out booked slots.
  • Offers page — browse platform promotions created by Admin.

3.2 Booking journey (login required)

Browse / Search hall → Hall detail → Choose date & slot → Booking form (event type, guests, contact) → Checkout (rent + deposit, 40% advance) → Simulated payment → Booking created as pending → Vendor must confirm.
  • Booking form captures event type, date, slot, guest count, name, phone, email, special requirements, optional promo code.
  • Checkout shows base rent, security deposit, total, and 40% advance payable.
  • Payment creates a booking code (BK-XXXXXX), a payment record (TXN-…, method “Razorpay Simulated”), and locks the calendar slot as pending.
  • Customer is redirected to the booking detail page with “awaiting vendor approval”.

4. Vendor — complete features

Vendors list halls and operate bookings. A new vendor cannot go live until Super Admin approval.

4.1 Onboarding

  • Vendor registration — split-screen UI; fields: name, email, password, business name, phone.
  • Account is created with role Vendor. Vendor profile is saved as verification_status = pending.
  • Pending Approval page — unapproved vendors are blocked from dashboard, halls, calendar, bookings, finance, and subscription by middleware.
  • Vendor login — dedicated /vendor/login screen.
  • After Admin approval, vendor can use the full panel.

4.2 Dashboard

  • Metrics: total bookings, upcoming confirmed events, pending bookings, completed bookings, monthly revenue, hall count, subscription status.
  • Recent bookings list and halls overview.

4.3 Hall management

  • Add / edit / delete / preview halls.
  • Cover photo upload.
  • Basic info: name, hall type, description, contact, email, address, city (used in customer search), area, pincode, map URL, landmark.
  • Capacity: seating, dining, floating, min/max guests.
  • Pricing: base, morning, evening, full-day, weekday, weekend, security deposit.
  • Policies: event timing, veg / non-veg, outside catering, outside decorator.
  • Amenities — select from master list; option to add a custom amenity.
  • Subscription hall limit — cannot add more halls than the active plan allows (default 1 if no plan).

4.4 Availability calendar

  • Month calendar per hall.
  • Block or unblock morning / evening / full-day slots (with optional reason).
  • Online and offline bookings automatically mark dates as booked and free them on cancel/reject.

4.5 Bookings

  • List all bookings; filter by status.
  • Confirm, reject, cancel, or complete a booking — calendar stays in sync.
  • Offline booking — vendor records a walk-in/phone booking (customer name, phone, event, date, slot, guests, amount, advance). Status starts as confirmed; code prefix BK-OFF-; calendar locked as booked.

5. Super Admin — complete features

Admin Portal is a full operations console. Access: /admin/login, role Admin only.

5.1 Dashboard

  • KPIs: total vendors, pending vendors, total halls, pending halls, live halls, total bookings, completed-payment revenue, total customers.
  • Queues: latest pending vendors and pending halls (quick approve).
  • Recent activity log.

5.2 Vendor management

  • Directory with status filter (pending / approved / etc.).
  • Vendor detail: business profile, halls, subscription, bookings.
  • Approve new vendors (unlocks Vendor panel).
  • Suspend and activate vendor accounts.
  • Actions written to the activity log.

5.3 Hall verification

  • All halls with status filter (draft / pending_review / live).
  • Review screen with media, amenities, pricing, policy, availability, reviews.
  • Approve → hall goes live on the customer site.
  • Request changes or reject with reason.

5.4 Bookings, customers, subscriptions

  • Booking ledger — all platform bookings; Admin can cancel a booking.
  • Customer directory — list customers; toggle active / blocked.
  • Subscriptions & plans — create and update subscription plans (name, price, hall limit, features).

6. End-to-end business flows

6.1 Vendor goes live

Vendor registers (business name + phone) → status Pending → Admin approves vendor → Vendor chooses subscription plan (dummy pay) → Vendor adds hall (city, pricing, policies, photo) → Hall can be reviewed by Admin → Live halls appear in customer search.

6.2 Customer books a hall

Customer searches by city/date (or GPS) → Opens hall → Picks date/slot → Checkout + 40% advance (simulated) → Booking pending + slot locked → Vendor confirms or rejects → Confirmed booking shows on customer dashboard → Customer can cancel, review, or download invoice.

6.3 Offline (vendor-side) booking

Vendor enters walk-in booking → Confirmed immediately → Calendar marked booked → Amounts appear in vendor finance.

9. Summary for Team Lead

The product is a working three-sided marketplace: customers can find and request halls; vendors can list inventory, control the calendar, take online and offline bookings, and see revenue; Super Admin can approve vendors, control listings, money, reviews, offers, tickets, and reports.

  • Customer path is complete from search through booking, invoice, wishlist, and reviews.
  • Vendor path is complete from registration and approval wait, through halls, calendar, bookings, finance, and plans.
  • Admin path is complete as an operations console, not only a dashboard.
